Connect entropy-server instances

Use the Socket lab for peer and self-links. For a server-side A → B link, register B in A's JSON source file, start A with -lab-sources=lab.json, then choose Registered server source. Set the base URL to A itself for a server-side self-link.

{"sources":[{"id":"peer","kind":"entropy-ws","endpoint":"http://127.0.0.1:8081"}]}

The operator controls registrations and bridge access. Loopback clients are allowed by default; remote access needs -lab-allow-remote and deployment access controls. A peer connection consumes its output without feeding it back into DRBG seeding.

HTTP body fetch

The Socket lab can fetch a prefix of response-body bytes (HTML, text or binary), not a rendered page. Browser mode follows ordinary redirects but needs the target to allow CORS. Most ordinary sites will block it.

For those sites, prepare a webpage registration using Register a source, load it with -lab-sources, then choose Registered server source in the Socket lab. Registrations support bounded prefixes, same-origin redirects, same-host HTTP→HTTPS upgrades and a pool of URLs sampled at random. HTTP 201 Created is a successful response, not a redirect; a Location header there identifies the created resource.

Structured web content is useful comparison data, not a cryptographic random source.

Source notes

Camera and microphone data comes from the computer running your browser and requires permission plus HTTPS or localhost. Camera pixels are browser-processed/resampled; audio is PCM16LE mono from the latest window and may overlap. Use the File lab for detailed local-file seeking.

Direct URLs follow browser CORS, Origin and mixed-content rules. Registered sources are read by entropy-server and need operator configuration; only source IDs are submitted. UDP registrations listen for datagrams at the configured address.

Cadence controls generators, HTTP, files, media, entropy-server links and registered bridges. Arbitrary WebSocket and serial sources arrive on their own clock. Direct WebSocket messages may contain up to the configured byte limit (at most 8 MiB); analysis uses the selected window. Sample size controls request/read sizes for the other adapters.

XOR needs two equal-length samples; LSB expands each low bit to a full byte. Transformations are labelled. These experimental tools describe the selected representation and do not certify cryptographic entropy.

Autocorrelation

          
          
Awaiting selected bytes.

          
The dashed reference is approximately ±1.96/√N under an independent uniform-source model, per lag. Multiple lags can cross it by chance. Constant input has undefined correlation.

        

        

          
Adjacent-byte transitions

          
          
Awaiting byte pairs.

          
Sliding adjacent pairs, grouped into labelled byte ranges. Brightness uses log(count + 1), relative to the current maximum. A flat histogram can still hide a predictable transition pattern.

        

        

          
Local entropy & bit balance

          
          
Awaiting complete blocks.

          
Two separate scales: bits/byte and fraction of one bits. Small random blocks normally estimate below eight bits/byte; the whole-sample alert threshold is not applied here.

        

        

          
Spectral history

          
          
Awaiting spectral history.

          
Uses the existing FFT window and fixed dB scale, before frame averaging. At most 120 sampled rows and 256 peak-preserving frequency groups. Rows have equal height; age labels show actual capture gaps. File rows show window offsets.
