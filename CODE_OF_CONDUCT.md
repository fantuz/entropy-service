# Code of Conduct

Entropy Service is an independently maintained, public open-source project. Its
issues, pull requests, code reviews, and other project discussion spaces should
be welcoming, technically constructive, and safe for participants.

## Our standards

When participating in this project, please:

- Treat people with respect, regardless of experience, background, identity, or
  technical opinions.
- Critique code, designs, evidence, and claims rather than attacking people.
- Assume good intent where reasonable; ask questions and acknowledge mistakes.
- Provide reproducible details and constructive feedback when raising concerns.
- Respect people's time: avoid repeated demands for immediate replies or support.
- Protect privacy: redact credentials, private keys, personal data, and sensitive
  infrastructure details before posting logs, screenshots, or benchmarks.

Unacceptable conduct includes harassment, threats, discrimination, personal
insults, stalking, unwanted sexual attention, publishing others' private
information without permission, deliberately disruptive behavior, and repeated
hostile or bad-faith interactions after a request to stop.

Strong technical disagreement is welcome. Personal attacks are not.

## Scope

This policy applies to project-maintained GitHub issues, pull requests, code
reviews, and any other spaces explicitly operated as part of Entropy Service.
It does not create obligations to moderate independent third-party spaces.
GitHub's own [Community Guidelines](https://docs.github.com/en/site-policy/github-terms/github-community-guidelines)
continue to apply on GitHub.

## Reporting concerns

For ordinary, **non-sensitive** moderation concerns, you may flag the discussion
in the relevant thread or open an issue with a short description. Do not post
private correspondence, identifying details of affected people, or allegations
that require confidential handling in a public issue.

For sensitive conduct concerns, contact the maintainer through a **private
contact method publicly offered on their [GitHub profile](https://github.com/fantuz)**,
if available. If no suitable private project channel is available, use GitHub's
[reporting and abuse tools](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam) for conduct occurring on GitHub.
This project does **not** currently promise a dedicated confidential moderation
mailbox or a fixed response-time SLA. Please do not assume a public GitHub
issue is confidential.

**Security vulnerabilities are different:** do not disclose exploits, private
keys, or other sensitive vulnerability details in public issues. Follow
[SECURITY.md](SECURITY.md) for the private-reporting procedure.

## Enforcement

The maintainer may, as appropriate, ask for edits, remove or hide contributions,
close or lock discussions, decline a pull request, or restrict participation.
Decisions are made on a best-effort basis, considering severity, recurrence,
project scope, and available moderation tools. The maintainer will aim to
minimize unnecessary disclosure of sensitive information, but cannot guarantee
confidentiality on third-party platforms.

This policy can be refined as the project and community grow.
