# Entropy Service v2.4.1 — bundled Windows GUI installer

This release adds a self-contained Windows x64 GUI installer alongside the existing portable CLI archives, Linux packages and containers. Both desktop views, both Go utilities and the private Python/GTK runtime install together; Go, Python and MSYS2 do not need installing separately.

## Windows GUI download and first run

- [Download Windows GUI setup](https://github.com/fantuz/entropy-service/releases/download/v2.4.1/entropy-service_2.4.1_windows_amd64_gui_setup.exe)
- [SHA-256 checksums](https://github.com/fantuz/entropy-service/releases/download/v2.4.1/checksums.txt)
- [Matching runtime source packages](https://github.com/fantuz/entropy-service/releases/download/v2.4.1/entropy-service_2.4.1_windows_amd64_gui_sources.zip) — optional for running the application; retained for provenance, licensing and rebuilding.

Run setup for your current user, then open **Entropy Server** and **Entropy Client** from the Start menu. No administrator elevation is required for the GUI installer. In the server window, click **Start** to launch a local server; then start the client. The bundled server shortcut begins with loopback HTTP at `127.0.0.1:8080`, HTTPS disabled for the initial demonstration. Configure certificates/HTTPS in Options before remote use. Ordinary CLI defaults retain HTTPS enabled.

The setup is **unsigned**: Windows can display Unknown publisher or SmartScreen warnings. Authenticode signing remains deferred. Verify the download against the release checksum manifest. See the [installer guide](https://github.com/fantuz/entropy-service/blob/v2.4.1/docs/windows-gui-installer.md) for paths, startup diagnostics, upgrades and uninstall.

## Packaging and release integrity

- Private Python/GTK libraries, typelibs, schemas, fonts, notices and package metadata are included. Relative GUI data/cache paths use `%LOCALAPPDATA%\Entropy Service`; the application installs under `%LOCALAPPDATA%\Programs\Entropy Service`.
- The installer includes server/client options, local process Start/Stop, server health monitoring and client waterfall/fullscreen views. Uninstall removes the application/runtime and retains user data outside the installation.
- A manifest records exact runtime package versions, licenses, matching complete source archives and hashes. Corresponding runtime source packages are published separately from the executable.
- Release publication requires actual install, GTK/client/server operation and uninstall tests while the original build-time MSYS2 prefix is unavailable. It publishes that tested installer without rebuilding, checks its version/tagged source and hashes, and includes both GUI assets in the same `checksums.txt` as native downloads.
- Native Windows Service management remains available from v2.4.0. Installing the per-user GUI does not register a service or modify firewall/trust stores. Persistent service installation is a separate elevated operation from a protected executable directory; see the [service guide](https://github.com/fantuz/entropy-service/blob/v2.4.1/docs/windows-service.md).

## Validation and compatibility

Focused version/artifact checks reject stale development installers, wrong source revisions, corrupt checksums, unexpected assets and unsafe/incomplete source archives. GitHub CI covers full Go/race/lint/vet and vulnerability checks, bounded fuzzing, Chromium/Firefox, Linux/Windows GTK, packaged Windows CLI/SCM, Linux systemd, endurance and the three container architectures. The native installer test exercises paths with spaces and data preservation. Linux distribution and CLI/native container features remain available. Native Windows ARM64 and Authenticode signing remain follow-ups.

After the tagged release and container publication complete, pull the matching images:

```sh
docker pull ghcr.io/fantuz/entropy-service:v2.4.1
docker pull ghcr.io/fantuz/entropy-client:v2.4.1
```

Docker selects the architecture automatically. Pin the image digest for an exact container build. Registry publication follows native release publication, so the two sets of downloads can become available at different times.
