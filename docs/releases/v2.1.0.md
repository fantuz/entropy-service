# Entropy Service v2.1.0 — diagnostics, languages and faster page loads

This release expands the browser tools, adds eight interface languages, hardens LAB access and makes repeated translated-page visits lighter. Linux remains the primary deployment target; Windows x64 support is retained.

## Highlights

- **Optional diagnostics:** autocorrelation, adjacent-byte transitions, local diagnostic strips and spectral history; PCM waveform/spectrum with optional 50/60 Hz notch comparison. Calculations are bounded and enabled when their panels are open.
- **Clearer graphs:** Classic, Blue/Orange and High Contrast palettes, saved selection and wider desktop workspaces.
- **Eight additional interface languages:** French, German, Spanish, Czech, Russian, Polish, Greek and Italian. Interface language is saved independently from word-list language, theme and palette. Documentation remains in English.
- **Faster page delivery:** content-versioned catalogs, encoding-specific ETags and startup-prepared gzip. Measured French/Greek cold catalog bodies are about 63% smaller; repeated navigation/reloads transfer no catalog body in the tested Chromium and Firefox configurations. Binary entropy responses explicitly send `Cache-Control: no-store`.
- **LAB hardening:** checks against the actual inbound HTTP Host, an explicit local-alias allowlist and safer Linux device-read ownership/cancellation.
- **Stronger validation:** repeatable traffic, simulated source faults and joined cleanup on Linux and Windows. Publishing waits for regression, browser, native Windows, packaged Windows and endurance checks.
- **Maintenance and evidence:** refreshed coverage and hardware examples, approved stale-material cleanup and a [measured performance assessment](https://github.com/fantuz/entropy-service/blob/v2.1.0/docs/linux-performance-2026-11-13.md). The terminal-renderer optimization already shipped in v2.0.4; this release documents its measured benefits.
- **Simpler downloads:** organized README badges and direct architecture buttons that follow the latest release automatically. Versioned files remain available; stable download aliases have their own entries in `checksums.txt`.

## Upgrade notes

- Intentional local LAB aliases now require `-lab-allowed-hosts=your.alias`. Ordinary localhost and literal loopback use remain supported. See [LAB safety](https://github.com/fantuz/entropy-service/blob/v2.1.0/docs/lab-safety.md) for remote and reverse-proxy configuration.
- Optional diagnostic panels start closed; the normal display cadence remains 5 FPS. The 20-FPS option is a maximum, with large/high-DPI views subject to available rendering capacity.
- Preparing static assets costs about 19 ms once at startup on the measured Linux VM and retains about 545 KiB of prepared bodies. The performance report records startup/RSS tradeoffs and the unresolved small-request and large-canvas follow-ups.
- Existing DRBG/reseed protections remain in place. Experimental hardware adapters still require their documented drivers/bindings and device qualification.
- Windows distribution remains an x64 portable console archive. Persistent Windows Service installation and installer signing remain separate follow-ups.
