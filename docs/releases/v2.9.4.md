# Entropy Service v2.9.4

The server desktop GUI can now find an existing local entropy-server when you open it. This release also makes it easier to start your first HTTPS server and to select a seed source on Linux.

## Monitor a local server

On a default launch, the GUI checks IPv4 and IPv6 loopback for HTTPS on port 8443. If HTTPS is unavailable, it also checks HTTP on port 8080, the default for the packaged Linux service. The GUI checks both liveness and readiness, so it can show a running server that reports degraded health. Use **Find local** to try again after starting the service.

When you launch a server from **Start**, the monitor follows the loopback listener and port selected in **Options**, including an HTTP-only listener on a custom port. You can still enter a remote URL and click **Connect**. An explicit monitoring choice takes precedence when you start a local server. [Desktop monitoring guide](https://github.com/fantuz/entropy-service/blob/v2.9.4/docs/desktop-gui.md#live-server-health)

## Set up HTTPS on your first run

Expand **Live server health → Set up a self-signed certificate** for a copyable command using the selected server executable. Run it from a private directory, then select the certificate and private key in **Options → Listeners and TLS**. On a packaged Linux installation, run

```sh
entropy-server generate-cert -if-missing
entropy-server-gui --health-ca="$PWD/cert.pem"
```

The public certificate lets the monitor verify the local server. An untrusted certificate stops automatic discovery so you can resolve the trust issue before connecting. The guide includes Windows PowerShell commands and examples with absolute paths. [Local HTTPS setup](https://github.com/fantuz/entropy-service/blob/v2.9.4/docs/desktop-gui.md#set-up-local-https)

## Choose a Linux seed source

The Linux server GUI now initially selects `/dev/urandom`, so a first run can use the operating system's random source. Operators with a hardware RNG can select its device in **Options** or pass it explicitly. This default applies to the desktop launcher.
