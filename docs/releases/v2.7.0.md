# Entropy Service v2.7.0 — client performance, adaptive pull and desktop controls

v2.7.0 makes server limits and client acquisition costs visible, adds optional
adaptive HTTP pull pacing, expands the shared desktop controls and improves
Windows upgrades. Linux, Windows and both macOS architectures remain supported.
Existing generator defaults, TLS verification and failure policies are preserved.

## Discover server limits and understand client performance

- `GET /v1/capabilities` advertises the configured sample maximum, acquisition
  transports and raw WebSocket interval range. It does not generate bytes or
  expose private paths, source registries or certificate/key material.
- Client `-capabilities=auto` checks recognized entropy-service routes once,
  before acquisition. A known limit violation stops startup with an explanation;
  older/custom servers retain auto-mode compatibility. `required` enforces
  discovery and `off` disables it. Discovery is bounded, uses existing TLS trust
  and refuses redirects.
- Terminal and desktop views distinguish requested/effective/average received
  FPS, received throughput and receive/analysis/output timings. The desktop
  **Connection & performance** section can be collapsed to give graphs more room.
- Optional `-report-performance` adds periodic JSONL progress independently of
  statistical sampling. The GUI enables it for supporting companions, so rates
  still update with long analysis intervals. Existing report consumers receive
  no additional record types by default; preview/history bounds are retained.

`below target` describes acquisition performance, independently of the Shannon
assessment. Receive wait includes server pacing, generation and transfer; it is
not a measurement of network latency alone. Fullscreen waterfall retains its
Shannon/threshold/status/throughput first line.

## Optional adaptive HTTP pull pacing

```sh
entropy-client -mode=pull -slice=33554432 -refresh=100ms \
  -adaptive -adaptive-max-interval=2s
```

Adaptive mode introduces headroom by slowing requests when observed receive and
processing costs exceed the requested cadence, then recovering gradually. The
original `-refresh` is the fastest permitted interval; the configurable ceiling
defaults to five seconds. Payload size, analysis prefix/interval, thresholds,
exports, request deadlines, retry budgets and fail-closed behavior remain intact.
Fixed pacing remains the default. WebSocket push remains server-paced and rejects
adaptive selection explicitly.

The [client guide](https://github.com/fantuz/entropy-service/blob/v2.7.0/docs/client-capabilities-performance.md)
includes protocol details, flags, interpretation, a real GUI screenshot and two
bounded Linux VM observations. Those short trials demonstrate the headroom
tradeoff; they are not physical RNG qualification or a Windows capacity claim.

## More desktop controls and useful failure reports

The Linux/Windows/macOS server GUI exposes LAB registry paths, trusted Host and
remote-access settings, connection/memory budgets, cookie preferences and the
existing loopback-only debug/pprof listener. **Edit features…** opens the options
editor beside the read-only validated indicators. Changes apply to the next
GUI-owned run; offline validation does not start listeners or open devices.

Client errors now reveal the reported transport/backend cause and automatically
open bounded, selectable diagnostics. URL credentials and query secrets are
redacted, including truncated stderr fragments. Guidance distinguishes incomplete
responses, timeouts, rejected sizes and reported generation failures; an EOF does
not imply a CPU failure. Samples up to 32 MiB can be received and fully analysed
while the waterfall remains a bounded prefix preview.

Mac shutdown waits for native fullscreen transitions before destroying the
window, and Ctrl+C follows the orderly close path. Native CI exercises immediate
fullscreen-close behavior on Intel and Apple Silicon, acquisition, progress with
a one-hour analysis interval and joined process cleanup.

## Windows installer upgrades

The per-user installer detects an existing installation and shows installed/setup
versions and location before replacement. It removes obsolete application/runtime
files, retains user state and one Apps registration, and offers a checked Finish
option to open the actual current-user Start Menu folder. Silent installs do not
open Explorer. Close active GUI/CLI processes before upgrading; leftover private
GTK helpers are handled without terminating unrelated system processes.

The installer includes both GUI views, both Go utilities and private Python/GTK
libraries. It remains unsigned. The [installer guide](https://github.com/fantuz/entropy-service/blob/v2.7.0/docs/windows-gui-installer.md)
describes replacement, retained files, development artifacts and provenance.

## CI cache maintenance

Closed-PR maintenance queries only that PR's exact cache refs. Concurrent cache
saves/evictions cause bounded retries from page one. Persistent churn defers
cleanup with an explicit zero-deletion warning/summary. Already-evicted cache
DELETE 404 responses are counted separately; malformed replies and listing/write
permission failures still fail. Open/unknown PRs, unrelated default-branch caches,
the two retained main compiler snapshots and deletion bounds remain protected.
The privileged workflow continues to execute default-branch code only.

The [CI guide](https://github.com/fantuz/entropy-service/blob/v2.7.0/docs/ci.md)
explains the pagination failure, conservative behavior and focused fault tests.
Full tagged publication retains Go quality/race/fuzz/vulnerability/terminal,
Firefox/Chromium, native and packaged Windows, both native Macs, endurance,
container/offline-registry and isolated Windows installer validation.
