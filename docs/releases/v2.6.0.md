# Entropy Service v2.6.0 — Linux, Windows, macOS and offline containers

v2.6.0 adds Intel and Apple Silicon macOS support and portable offline container
archives. Linux and Windows distributions remain included: both CLI utilities,
Linux DEB/RPM packages, the Linux desktop interface, and the bundled Windows GUI
installer. Existing Linux/Windows generator defaults and hardware support are
retained.

## macOS server and client

- Native CLI archives for Intel (`darwin_amd64`) and Apple Silicon
  (`darwin_arm64`), each containing `entropy-server` and `entropy-client`.
- The server defaults to `-device=macos-csprng`, using Go's native OS random
  source for seeding. Apple Silicon defaults to ChaCha20; Intel to AES-256-CTR.
- Adaptive terminal sizing, waterfall/fullscreen rendering, private file and
  network exports, raw stdout and cancellable JSONL report pipes.
- A Homebrew GTK launcher for both desktop views: startup options, GUI-owned
  Start/Stop, live server health, client waterfall, palettes and fullscreen.
  Install dependencies with `brew install gtk4 pygobject3`, obtain the matching
  source archive, and follow the [macOS guide](https://github.com/fantuz/entropy-service/blob/v2.6.0/docs/macos.md).
- Go clients use macOS Keychain trust. The Homebrew GUI health checker uses
  Python/OpenSSL roots; `--health-ca` accepts a deployment's public CA/certificate.
  Neither path disables TLS verification or imports the server's private key.

Mac CLI archives are unsigned/not notarized. The GUI is a Terminal launcher
with Homebrew dependencies, rather than a self-contained `.app`. Native
Quantis/ChaosKey adapters, Linux random-device injection and system service
management are unavailable on macOS; unsupported requests fail explicitly.
OS random reads check cancellation/deadlines between bounded reads and after
an in-flight OS call, rather than abandoning a worker.

## Offline OCI downloads and registry reliability

Two new release assets distribute the exact tested server and client images:

- [Server OCI archive](https://github.com/fantuz/entropy-service/releases/download/v2.6.0/entropy-service_2.6.0_linux.oci.tar)
- [Client OCI archive](https://github.com/fantuz/entropy-service/releases/download/v2.6.0/entropy-client_2.6.0_linux.oci.tar)

Each archive contains Linux amd64, ARM64 and ARMv7. Runtime tests and Trivy scans
validate the OCI exports before their unchanged manifests/blobs are combined.
The archive's root index digest matches its versioned GHCR index. Import a
platform into Docker or copy all platforms to an internal registry with Skopeo;
see the [container guide](https://github.com/fantuz/entropy-service/blob/v2.6.0/docs/containers.md#offline-oci-downloads).
These are Linux container images, including when Docker Desktop hosts them on
Windows or macOS.

The real publisher now has integration tests against a digest-pinned local
registry: successful/repeated publication, HTTP 503, missing-blob recovery and
permanent denial. Both role graphs and all six SBOMs are staged before public
aliases move. Registry APIs cannot atomically update two repositories; an
idempotent rerun repairs a failure during the final alias updates. Existing
stable `latest` reconciliation and older validated-publication recovery remain.
Single-bundle downloads now use explicit destination directories in normal
publication and recovery, correcting the artifact downloader's one-match
flattening that blocked the first OCI-based GHCR publication on `main`.

## Desktop maintenance and validation

- Avoid redundant TLS-context/root initialization during GUI health polling on
  newer Python releases, including plain-HTTP observations.
- Preserve independent health-endpoint deadlines, verified TLS and joined
  shutdown of owned server/client processes.
- Native macOS CI tests actual checksummed Mach-O archives on both CPU
  architectures, Go race/vet, HTTP/WebSocket acquisition, HTTPS/WSS rejection,
  private exports, stdout cancellation, PTY geometry and shutdown.
- Actual GTK tests cover options, server ownership, live-health faults, native
  waterfall painting, resizing, palettes, fullscreen completion/failure and
  closing a client during a fullscreen transition. Mac fullscreen cases use
  separate native application processes to match AppKit's lifecycle.
- Full tagged validation also retains Linux/Windows regression, Firefox and
  Chromium, fuzzing, vulnerability checks, endurance, packaged systemd/Windows
  Service lifecycle tests, all three container platforms and installer testing.

The Windows installer contains both GUI views, both Go utilities and private
Python/GTK libraries; a separate Go/Python/MSYS2 installation is unnecessary.
Open **Entropy Server** or **Entropy Client** from the Start menu. It remains
unsigned. [Matching runtime sources](https://github.com/fantuz/entropy-service/releases/download/v2.6.0/entropy-service_2.6.0_windows_amd64_gui_sources.zip)
are available separately for licensing and rebuilds.

Linux desktop launch instructions remain in the
[desktop guide](https://github.com/fantuz/entropy-service/blob/v2.6.0/docs/desktop-gui.md).
Use the matching source tree with its Python/GTK dependencies for the Linux or
Mac GUI; the portable CLI archives do not bundle that runtime.

Verify downloads using [SHA-256 checksums](https://github.com/fantuz/entropy-service/releases/download/v2.6.0/checksums.txt).
After container publication completes:

```sh
docker pull ghcr.io/fantuz/entropy-service:v2.6.0
docker pull ghcr.io/fantuz/entropy-client:v2.6.0
```

Native/GUI assets appear before GHCR publication completes. `latest` follows
the published stable release; pin a digest for an exact container build.
